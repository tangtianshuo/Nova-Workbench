  <behavior>
    - updateTask(taskId, updates): 在嵌套 categories[].tasks[] 中找到任务,合并 updates,返回新 state;找不到任务时返回原 state (no-op)
    - deleteTask(taskId): 从嵌套结构中移除任务,返回新 state
    - reopenTask(taskId): 把 task.status 设为 '未开始'
    - moveTask(taskId, fromCatId, toCatId): 从 fromCatId 移除,push 到 toCatId.tasks 顶部
    - setTaskProject(taskId, projectId?): 设置 task.projectId;若 productId 在 productStore 中存在,同步设置 task.project = product.name (D-10 镜像);若 projectId 为 undefined,清空 task.projectId 且 task.project 设为 ''
    - migrate(persisted, version): 当 version < 2 时,遍历 categories[].tasks[] 给每个 task 补 projectId: undefined, scheduledEventId: undefined (可选字段,实际不写入,但确保结构存在);version >= 2 时 passthrough
    - addTask 不再硬编码 ID;调用方传入 task 对象已带 id (crypto.randomUUID())
  </behavior>
  <action>
1. 编辑 `src/data/mockTasks.ts`:
   - Task 接口在 `project: string` 之后加 `projectId?: string;` 和 `scheduledEventId?: string;` 两个可选字段
   - INITIAL_CATEGORIES mock 数据**不要加 projectId 字段**(由 migrate 函数兜底;mock 数据保持精简)

2. 编辑 `src/stores/taskStore.ts`:
   - 顶部加 `import { useProductStore } from './productStore';` (用于 setTaskProject 读取 product.name 做 D-10 镜像)
   - TaskState 接口添加 5 个新 action 签名:
     ```typescript
     updateTask: (taskId: string, updates: Partial<Task>) => void;
     deleteTask: (taskId: string) => void;
     reopenTask: (taskId: string) => void;
     moveTask: (taskId: string, fromCatId: string, toCatId: string) => void;
     setTaskProject: (taskId: string, projectId: string | undefined) => void;
     ```
   - 在 create(persist(...)) 内部实现 5 个 action:
     - `updateTask`: `set((state) => ({ categories: state.categories.map((cat) => ({ ...cat, tasks: cat.tasks.map((t) => t.id === taskId ? { ...t, ...updates } : t) })) }))`
     - `deleteTask`: `set((state) => ({ categories: state.categories.map((cat) => ({ ...cat, tasks: cat.tasks.filter((t) => t.id !== taskId) })) }))`
     - `reopenTask`: 调用 updateTask(taskId, { status: '未开始' }) (复用,避免重复逻辑)
     - `moveTask`: `set((state) => { const fromCat = state.categories.find(c => c.id === fromCatId); const toCat = state.categories.find(c => c.id === toCatId); if (!fromCat || !toCat) return state; const task = fromCat.tasks.find(t => t.id === taskId); if (!task) return state; return { categories: state.categories.map((cat) => { if (cat.id === fromCatId) return { ...cat, tasks: cat.tasks.filter(t => t.id !== taskId) }; if (cat.id === toCatId) return { ...cat, tasks: [task, ...cat.tasks] }; return cat; }) }; })`
     - `setTaskProject`: `set((state) => { const productName = projectId ? useProductStore.getState().products.find(p => p.id === projectId)?.name : ''; return { categories: state.categories.map(cat => ({ ...cat, tasks: cat.tasks.map(t => t.id === taskId ? { ...t, projectId, project: productName ?? '' } : t) })) }; })` (注意:用 `useProductStore.getState()` 而非 hook,因为 store action 不能调 hook)
   - persist 配置 `version: 1` 改为 `version: 2`
   - migrate 函数从 passthrough 改为:
     ```typescript
     migrate: (persisted: any, version: number) => {
       if (!persisted || !persisted.categories) return persisted as Partial<TaskState>;
       if (version < 2) {
         // v1 → v2: 给每个 task 补 projectId/scheduledEventId 默认 undefined
         persisted.categories = persisted.categories.map((cat: any) => ({
           ...cat,
           tasks: (cat.tasks || []).map((t: any) => ({
             ...t,
             projectId: t.projectId ?? undefined,
             scheduledEventId: t.scheduledEventId ?? undefined,
           })),
         }));
       }
       return persisted as Partial<TaskState>;
     },
     ```

3. **不修改 addTask 的 ID 生成逻辑** — ID 生成是调用方责任 (TaskKanban / TaskDialog 在 create 模式下传 `crypto.randomUUID()`)。store 只负责去重 (现有 `if (state.categories.some((cat) => cat.tasks.some((t) => t.id === newTask.id))) return state;` 保留)。
