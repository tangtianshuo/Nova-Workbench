# Phase 5 — Task CRUD 补全 UI Design Contract

> Visual and interaction contract for TaskKanban inline editing, DnD, TaskDialog, and the new reusable Drawer. Generated by gsd-ui-researcher from CONTEXT.md (12 decisions locked).

This phase reuses the existing design system. **No new color tokens, no new typography scale, no new radius scale.** The contract below fixes layout, spacing, and interaction details so the planner and executor make zero ad-hoc visual decisions.

## Component Layout Contracts

### 1. TaskKanban Expanded Card (D-01, D-02, D-03, D-04)

The expanded card replaces the current "preview-only" expanded state with always-editable inputs. The card keeps its existing outer shell (`bg-bg-primary rounded-[var(--radius-md)] p-3 border` + `border-accent shadow-md ring-1 ring-accent/15` when expanded).

**Header row (collapsed + expanded share this):**
```
[id-mono 11px]  [title Input — grows]          [DotsThree DropdownMenu trigger]
```
- ID stays as `font-mono text-[10px] text-text-tertiary`
- Title: when expanded → `<Input variant="borderless">` (no border until focus, `h-7 px-1 -mx-1 text-sm font-medium`, full width); when collapsed → existing static text
- DotsThree button: `<Button variant="ghost" size="xs">` with `DotsThree` icon (size 16, `weight="duotone"`); `aria-label="任务操作"`

**Expanded body** (replaces existing `mt-3 pt-3 border-t` section):

Vertical rhythm `space-y-3` (12px between rows). Each row is a labeled mini-field unless noted.

| Row | Field | Control | Size |
|-----|-------|---------|------|
| 1 | Description | `<Textarea>` (auto-resize, min-h-[60px], no label, placeholder `"添加描述..."`) | full width |
| 2 | Meta grid (2 columns) | grid `grid-cols-2 gap-2` | — |
| 2a | Priority | `<Select>` 优先级: 高/中/低 | `h-8` |
| 2b | Due date | `<DatePickerInput>` | `h-8` (compact trigger) |
| 3 | Category | `<Select>` 分类: list of categories | `h-8` |
| 4 | Association row (optional, only when `projectId` set) | `<Badge variant="accent">` clickable → opens Drawer | `text-[10px]` |
| 5 | AI suggestions (existing block, preserve as-is) | — | — |
| 6 | Footer action row | `Button variant="primary"\|secondary size="sm" className="w-full"` | existing |

**Behavior notes:**
- No "Save" button anywhere on the card. All fields auto-save (D-02).
- Status field is NOT rendered as a Select on the card (D-04). Only the bottom main button toggles 完成/重新打开.
- Click on any input does NOT bubble to the card's click-to-collapse handler. Use `onClick={(e) => e.stopPropagation()}` wrapper on the expanded body (existing pattern).
- Combobox (product selector) is NOT on the expanded card — only in TaskDialog.

### 2. DotsThree DropdownMenu (D-03)

Uses existing `DropdownMenu` primitives. Items in fixed order:

| # | Item | Icon (Phosphor duotone, size 14) | Behavior | Disabled when |
|---|------|----------------------------------|----------|--------------|
| 1 | 在对话框中编辑 | `PencilSimple` | Opens TaskDialog in `mode="edit"` | never |
| 2 | 复制 ID | `Copy` | `navigator.clipboard.writeText(task.id)` + Toast success | never |
| — | separator | — | — | — |
| 3 | 重新打开 | `ArrowCounterClockwise` | Calls `reopenTask(task.id)` | `task.status !== '已完成'` |
| 4 | 删除 | `Trash` (color: `text-danger`) | Opens delete confirmation Dialog | never |

**Menu content sizing:** `min-w-[10rem]` (slightly wider than default 8rem to fit "在对话框中编辑" without wrap). Items use existing `DropdownMenuItem` padding.

The trigger button position: absolute top-right of card, `top-3 right-3`. Already where the CheckCircle indicator was — replace it. When `status === '已完成' && !isExpanded`, show BOTH a small `CheckCircle` (existing) AND the DotsThree (new). The CheckCircle moves to `top-3 right-10` to avoid overlap.

### 3. DnD Visual Feedback (D-05, D-06)

| State | Visual |
|-------|--------|
| Idle | Normal card styling |
| Activating (mouse down, < 8px move) | No visual change — looks identical to click |
| Dragging (> 8px move) | Dragged card: `opacity-60 scale-[1.02] shadow-shadow-lg cursor-grabbing`. Use motion values, spring `{ stiffness: 500, damping: 30 }` for the scale. |
| Drop target column (over) | Column container gets `ring-2 ring-accent/40 rounded-[var(--radius-md)]` and slightly elevated bg (`bg-bg-tertiary/50`) |
| Other cards in target column | Subtle shift via `layout` prop — `motion.div layout` with spring `{ stiffness: 400, damping: 30 }` |
| Drop | Card animates into final slot using same `layout` spring |

**Real-time count badge (D-06):** The column header `<Badge variant="neutral">` count updates during drag, not after drop. Implementation: derive count from `activeDragId` + `overColumnId` rather than waiting for the store mutation. Number change animates with `<motion.span key={count}>` (exit y:-4 opacity:0, enter y:4 opacity:0→1, spring 400/25).

**`DragOverlay` strategy:** Use `@dnd-kit/core`'s `<DragOverlay>` to render a portal-rendered clone of the card. This avoids layout shift in the source column. The clone uses the same card styling at `opacity-90 rotate-2 shadow-shadow-xl`.

### 4. TaskDialog (D-08, D-09, D-10)

Uses existing `Dialog` / `DialogContent` / `DialogHeader` / `DialogBody` / `DialogFooter`.

**Sizing:** `max-w-md` (448px). Tighter than CreateProductModal — task has fewer fields.

**Header:** `title={mode === 'create' ? '新建任务' : '编辑任务'}` `description={mode === 'create' ? '快速记录一个新任务' : `编辑 ${task.title}`}`.

**Body — field order and controls** (`DialogBody` provides `px-5 py-4 space-y-4`):

| # | Field | Control | Validation |
|---|-------|---------|------------|
| 1 | 标题 | `<Input>` placeholder `"任务标题"`, `autoFocus` in create mode | required; submit disabled when empty |
| 2 | 描述 | `<Textarea>` placeholder `"详细描述..."` `min-h-[80px]` | optional |
| 3 | Grid 2 cols: 优先级 / 分类 | `<Select>` 优先级 (高/中/低) + `<Select>` 分类 (categories) | defaults: 中, first category |
| 4 | Grid 2 cols: 截止日期 / 状态 | `<DatePickerInput>` + `<Select>` 状态 (未开始/进行中/已完成) | status visible here in dialog (unlike card per D-04) |
| 5 | 关联产品 (Combobox) | **New Combobox component** (see below). Label `"关联产品 (可选)"`. Default: empty. | optional |

**Combobox (D-09):**
- Built from `<Popover>` + `<Input>` (search) + filtered list. DO NOT use Radix Combobox (not installed).
- Trigger: `<button>` styled exactly like `SelectTrigger` (`h-9 px-3 rounded-[var(--radius-md)] bg-bg-input border border-border text-text-primary flex items-center justify-between`). Shows selected product name or placeholder `"搜索产品..."`.
- PopoverContent: `w-72 max-h-[240px] overflow-y-auto p-1`, list of `button` rows (`px-2.5 py-1.5 text-sm rounded-[var(--radius-sm)] hover:bg-bg-secondary`)
- Filter: case-insensitive substring on `product.name`
- Empty state inside dropdown: `"未找到匹配的产品"` (centered, `text-xs text-text-tertiary py-6`)
- Clear button: small `X` inside trigger when value set, sets productId to undefined.

**Footer:**
- Cancel: `<Button variant="secondary">取消</Button>` → `onClose()`
- Primary: `<Button variant="primary">{mode === 'create' ? '创建任务' : '保存修改'}</Button>` → submit handler
- Delete (edit mode only): `<Button variant="danger" size="sm">删除</Button>` placed on the LEFT (`mr-auto`), opens delete confirmation as nested Dialog.

**Form state reset (Pitfall P13):** When `open` transitions `false → true`, all field state resets from the `task` prop (edit mode) or to defaults (create mode). Use `useEffect([open, mode, task?.id])`.

### 5. Drawer Component (D-11, D-12) — NEW primitive

`src/components/ui/Drawer.tsx`. Reusable, will be re-used by Phase 9 chat panel.

**API:**
```ts
interface DrawerProps {
  open: boolean;
  onOpenChange: (open: boolean) => void;
  side?: 'right';           // only 'right' shipped this phase; Phase 9 may add 'left'
  width?: number;           // default 360, Phase 9 will pass 480
  children: ReactNode;
  // Optional header LabSlot
  title?: string;
  description?: string;
}
```

**Composition (mirrors Dialog):**
- `Drawer` (root, uses Radix `DialogPrimitive.Root` under the hood — same a11y semantics, ESC + outside-click supported)
- `DrawerContent` — fixed right-anchored panel
- `DrawerHeader` — title + description + close button (reuse X icon, `Button variant="ghost" size="sm"`)
- `DrawerBody` — scrollable content area
- `DrawerFooter` — optional sticky footer for actions

**Why built on Radix Dialog, not a fresh component:** Radix Dialog already provides focus trap, scroll lock, ESC, and outside-click. We only swap the animation axis (translateX vs scale) and anchor (right vs center). This is the lazy/correct move — reuse what the trust boundary already covers.

**Animation:**
```tsx
<motion.div
  initial={{ x: '100%' }}
  animate={{ x: 0 }}
  exit={{ x: '100%' }}
  transition={{ type: 'spring', stiffness: 350, damping: 34 }}
/>
```
Stiffer damping than the page transition (30 → 34) so the drawer doesn't bounce-overshoot on desktop.

**Overlay:** `fixed inset-0 z-modal bg-bg-overlay backdrop-blur-sm` — same as Dialog overlay. Overlay fades in via its own `initial={{ opacity: 0 }} animate={{ opacity: 1 }}`.

**Sizing tokens:**
- Width: `style={{ width: \`${width}px\` }}` default 360
- Height: `top-0 bottom-0 right-0` (full viewport height)
- Internal: header `px-5 pt-5 pb-3`, body `px-5 pb-4 overflow-y-auto`, footer `px-5 py-4 border-t border-border-subtle`
- z-index: `z-modal` (matches Dialog; Drawer is mutually exclusive with Dialog in this phase — never both open at once)

**Close affordances:**
1. ESC key (Radix built-in)
2. Click on overlay (Radix built-in)
3. X button in header (top-right)
4. Explicit cancel button in footer (when present)

## Destructive & Confirmation Patterns

Per REQUIREMENTS.md Key Decision #7: confirmation dialog, no undo.

| Action | Confirmation | Implementation |
|--------|--------------|----------------|
| Delete task (from DotsMenu OR TaskDialog) | Required — opens nested Dialog with title "删除任务?" + body using task title | Confirm button uses `<Button variant="danger">删除</Button>`. On confirm: call `deleteTask(task.id)`, close both the confirm and (if open) the TaskDialog, show success Toast "任务已删除". |
| Reopen task | None — immediately calls `reopenTask` | Disabled in DotsMenu when task not 已完成 |
| Move task (DnD) | None — drop commits immediately | No undo; if user mis-drops they drag again |
| Mark complete / reopen (bottom button) | None | Toggle is reversible by clicking again |
| Edit inline fields | None — debounced autosave | Failures surface as toast |

Delete confirmation uses a **nested `<Dialog>`** rendered inside TaskDialog, OR a top-level Dialog rendered in the kanban — pick whichever is simpler per call site. Both are valid because the existing `Dialog` primitive supports stacking via z-modal.

## Interaction Contracts (Locked Behaviors)

### Inline Save (D-02)
- **Debounce:** 400ms from last input event
- **Per-field:** Each field debounces independently (changing title then quickly description doesn't share a timer)
- **Save pulse:** On debounce fire, the input's border briefly transitions `border-border → border-accent → border-border` over 200ms. Implement via a `useState` `justSaved` flag + `setTimeout(reset, 200)`.
- **Unload guard:** If the user collapses the card or navigates away with pending changes, fire save immediately (flush debounce) before unmount.
- **Concurrent edits:** Out of scope (deferred — see CONTEXT.md).

### Click vs Drag Disambiguation (D-05)
- `PointerSensor` with `activationConstraint: { distance: 8 }`
- Click (≤ 8px movement) → toggles expand/collapse as today
- Drag (> 8px movement) → does NOT toggle expand; once drop completes, the card remains in its prior expand state
- Touch sensors: not configured (desktop app). If needed later, add `TouchSensor` with `delay: 150, tolerance: 8`.

### Real-time Count Badge (D-06)
- During drag, derive each column's count from: `currentCount + (thisColumnIsSource ? -1 : 0) + (thisColumnIsOver ? +1 : 0)`
- Animate the count value with `<motion.span key={derivedCount}>` (AnimatePresence)
- On drop, the store mutation makes the derived value match the persisted value — no visual snap because the values are identical.

### Form State Reset (Pitfall P13)
- TaskDialog: `useEffect(() => { reset all fields }, [open, mode, task?.id])` — when dialog opens or switches task, fields sync from source
- Only start debounce timers after the form is "dirty" (user actually typed), not from the programmatic seed

### Drawer Open/Close Focus
- Drawer opens on Badge click → focus moves into Drawer (Radix Dialog handles focus trap)
- Drawer closes via ESC / overlay / X / 打开详情 → focus returns to the Badge that triggered it (Radix handles this if the Badge is the trigger)
