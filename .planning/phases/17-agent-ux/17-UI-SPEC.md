# Phase 17 — UI Design Contract

> Visual and interaction contract for Agent UX (UX-01..04). ARCH-01/02 are docs-only — no UI.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Design system stance:** identical to Phase 15/16 (approved 2026-08-15). Nova's design system is established and LOCKED (CLAUDE.md: tech stack locked, no re-design; shadcn gate not applicable — custom token system). This contract specifies ZERO new design tokens, ZERO new primitives beyond one Radix package, and exactly ONE new npm dependency: `@radix-ui/react-context-menu` (mandated verbatim by UX-04; same Radix family as the existing 11 `@radix-ui/*` packages). ## Surface Contracts

### Surface 1: AgentConsole 双宿主 (UX-01)

**Locations:** extraction from `src/components/ChatPanel.tsx` into a shared component (suggested `src/components/AgentConsole.tsx` — exact file split is executor discretion); hosts: ChatPanel Drawer + rewritten `src/views/AgentWorkspaceView.tsx`. The current 309-line mock view is deleted in full (locked decision).

**DECISION (discretion resolved) — conversation state ownership:** messages / input / streaming / loading / pending HITL cards / `sessionRef` move out of ChatPanel component state into ONE transient zustand store (suggested `src/stores/chatConsoleStore.ts`, NOT persisted — same transient class as modal flags). Rationale: ChatPanel (mounted in Sidebar) and AgentWorkspaceView (mounted on `activeTab === 'agent'`) can be live simultaneously; two independent `useState` instances would fork the conversation and double-run session restore. A shared store makes the two hosts literally the same conversation ("功能一致" by shared state, not by hopeful symmetry). The restore effect runs from the store's first consumer; `restoreLatestSession` already has module-level promise dedupe (Phase 14, STATE.md) so double-mount is safe. `sessionRef` becomes a module-level ref inside the store file.

**ChatPanel after extraction (Drawer host) — zero visual diff:**

```tsx
<Drawer open={isOpen} onOpenChange={setOpen}>
  <DrawerContent width={480} className="max-w-[100vw]"
    onOpenAutoFocus={(event) => { event.preventDefault(); /* focus console textarea */ }}>
    <DrawerHeader title="AI 助手" description={`当前 provider：${PROVIDER_LABELS[provider]}`} />
    <AgentConsole />
  </DrawerContent>
</Drawer>
```

AgentConsole owns the full column chrome (replaces `DrawerBody`/`DrawerFooter` usage — same values): body `flex-1 overflow-y-auto px-5 pb-4 space-y-4`, footer `border-t border-border-subtle px-5 py-4`. All interior JSX (messages, ToolTrace, HITL cards, PrdDraftDialog, empty state, input form, Enter hint) moves verbatim from ChatPanel.tsx:509-659. The only additions: the carry chip row (Surface 2) above the footer form, and a `layout` distinction below.

**AgentWorkspaceView (page host):**

```tsx
export function AgentWorkspaceView() {
  return (
    <div className="mx-auto flex h-[calc(100dvh-var(--titlebar-h)-var(--header-h)-48px)] w-full max-w-3xl flex-col gap-4">
      <MorningReport />   {/* Surface 3; renders null when not due or no content */}
      <Card variant="glass" className="flex min-h-0 flex-1 flex-col overflow-hidden">
        <AgentConsole layout="page" />
      </Card>
    </div>
  );
}
```

**Interaction contract:**
- Page host renders the console column centered at `max-w-3xl` (chat-in-a-page convention; Drawer host stays 480px edge-anchored). Message bubbles keep `max-w-[88%]` in both.
- Conversation survives host switches mid-flight: open Drawer while on the agent tab (or vice versa) shows the same messages, streaming state, and pending cards from the shared store. Switching tabs away and back must not re-run restore or duplicate history.
- Page host shows NO provider label (drawer header keeps it). Deliberate: provider is ambient config owned by Settings; "功能一致" covers conversation capability, not chrome duplication.
- Input focus: Drawer host auto-focuses textarea on open (existing behavior). Page host focuses on mount.
- Empty state (no conversation): the existing Sparkle hero (`ChatPanel.tsx:510-516`) renders in both hosts — in the page host it sits below the morning report, which is the dominant visual (locked: 无会话时晨报占据主视觉).

### Surface 2: ⌘K 携带视图上下文 + chip 行 (UX-02)

**Location:** `src/hooks/useCmdK.ts` (bare binding), `src/stores/uiStore.ts` (carry state), `src/ai/context.ts` (`buildCoreContext` extension), AgentConsole footer (chip row).

**DECISION (discretion resolved) — carry state model:** uiStore gains a TRANSIENT (excluded from `partialize`, never persisted) `agentContextCarry: CarriedContextItem[]` where `CarriedContextItem = { kind: 'product' | 'task' | 'schedule'; id?: string; label: string; count?: number }`, plus `setAgentContextCarry` and `removeCarriedItem(kind, id?)`. A helper `refreshAgentCarry()` (same file or a small `src/ai/context.ts` sibling) snapshots the current view context into it and is invoked at ChatPanel-open time (⌘K, Shift+K, Sidebar AI button all route through the same open path). Carry derivation per locked decision:

| activeTab | Carry |
|-----------|-------|
| `product-management` | selected product (`selectedProductId` → `{kind:'product', id, label: name}`) |
| `tasks` | `selectedTaskId` if set; **fallback: current kanban list filter** — DECISION: lift TaskKanban's `viewMode` (+ active category name in category view) into uiStore transient fields so the filter is reachable at ⌘K time; TaskKanban reads them instead of local state |
| `schedule` | today's events window: one item `{kind:'schedule', label:'今日日程', count: n}` derived from `scheduleStore.events` filtered to today |

**⌘K binding (useCmdK.ts):**

```ts
if (meta && !event.shiftKey && key === 'k') {
  event.preventDefault();
  event.stopPropagation();
  refreshAgentCarry();
  const s = useUIStore.getState();
  s.setChatPanelOpen(!s.isChatPanelOpen);
}
```

Bare ⌘K/Ctrl+K and the existing Shift+K both open the same panel with the same carry (Shift+K branch adds `refreshAgentCarry()` too). Tauri webview has no URL-bar conflict (locked); Shift+K stays as web-dev fallback (locked).

**Chip row — rendered in AgentConsole footer, above the input form, both hosts:**

```tsx
{carry.length > 0 && (
  <div className="mb-2 flex flex-wrap items-center gap-1.5">
    <span className="text-xs text-text-tertiary">已携带:</span>
    {carry.map((item) => (
      <span key={`${item.kind}-${item.id ?? 'default'}`}
        className="inline-flex items-center gap-1 rounded-full border border-accent/20 bg-accent-subtle px-2 py-0.5 text-xs text-accent">
        {item.kind === 'schedule' ? `今日日程 (${item.count})` : item.label}
        <button type="button" onClick={() => removeCarriedItem(item.kind, item.id)}
          aria-label={`移除 ${item.label}`} className="shrink-0 hover:text-accent-hover">
          <X size={10} />
        </button>
      </span>
    ))}
  </div>
)}
```

**Interaction contract:**
- `×` removal is session-scoped (transient): the item leaves the carry until the next `refreshAgentCarry()` at a future open. No persistence, no toast.
- `buildCoreContext()` (context.ts) extends its "业务事实" section with carried items — selected task emits `- Selected Task: [priority] title (deadline …)`; schedule carry emits today's events lines; product carry uses the existing Selected Product section. Same core segment, same 600-token clamp — NO second assembler path (locked). The chip row is the visible truth of this injection: what the chips show is what the next send carries.
- Chip removal must affect the NEXT send (assembler reads the store at send time).
- Chips never render when carry is empty (product view with nothing selected → carry stays `[]` → no row).

### Surface 3: 晨报结构化卡片 (UX-03)

**Location:** new component (suggested `src/components/MorningReport.tsx`), rendered by AgentWorkspaceView only — never in the Drawer host.

**Data (locked — pure queries, zero LLM):** 今日日程 from `scheduleStore.events` (date === today, time-sorted); 过期未完成任务 from `taskStore` (status not 已完成/done AND deadline overdue — NOTE: `Task.deadline` is free text ('2025-05-16', '明天 12:00'); the overdue filter must skip unparseable deadlines, never crash); 待确认记忆候选 from `getMemoryStore().listPending()`.

**DECISION (discretion resolved) — daily semantics:** the zone renders on the FIRST mount of AgentWorkspaceView per local day. On that first mount, write the stamp `localStorage['morning-report:last-shown'] = yyyy-MM-dd` regardless of content (an empty report still counts as shown — it must not re-check on every tab switch). Remounts later the same day render `null` entirely (no hero, no collapsed bar). "Conversation started" = console store `messages.length > 0`; when it flips, an expanded report collapses to the top bar. Collapse/expand within a visit is component state and survives nothing.

**Expanded (no conversation — hero):**

```tsx
<Card variant="default" className="p-5">
  <div className="flex items-center justify-between">
    <div className="flex items-center gap-2">
      <Sparkle size={16} weight="duotone" className="text-accent" />
      <span className="text-sm font-semibold text-text-primary">晨报</span>
      <span className="text-xs text-text-tertiary">{formatChineseDate(today)}</span>
    </div>
    <Button variant="ghost" size="sm" onClick={collapse} aria-label="收起晨报"><CaretUp size={14} /></Button>
  </div>
  <div className="mt-4 space-y-4">
    {/* one <section> per non-empty segment; empty segments are omitted, not shown as "(无)" */}
  </div>
</Card>
```

Section header + item row (今日日程 shown; the other two follow the same shape):

```tsx
<div className="flex items-center gap-1.5 text-xs font-medium text-text-secondary">
  <CalendarDots size={14} weight="duotone" />
  今日日程
  <span className="text-text-tertiary">({events.length})</span>
</div>
<div className="mt-1.5 space-y-0.5">
  {events.map((ev) => (
    <button key={ev.id} type="button" onClick={() => jumpTo('schedule')}
      className="flex w-full cursor-pointer items-center gap-2 rounded-[var(--radius-md)] px-2 py-1.5 text-left text-sm text-text-primary transition-colors hover:bg-bg-secondary">
      <span className="shrink-0 text-xs tabular-nums text-text-tertiary">{ev.time}</span>
      <span className="truncate">{ev.title}</span>
    </button>
  ))}
</div>
```

Segment icons: 今日日程 `CalendarDots`; 过期任务 `Warning` with `text-warning`; 待确认记忆候选 `Brain`. Item secondary text: schedule = `{time}` prefix; task = `{deadline} · {priority badge-ish text}`; memory = candidate `{content}` (single-line truncate, click → ChatPanel).

**Collapsed (conversation started):**

```tsx
<button type="button" onClick={expand}
  className="flex w-full cursor-pointer items-center gap-3 rounded-[var(--radius-lg)] border border-border-subtle bg-bg-primary px-4 py-2 text-xs text-text-secondary transition-colors hover:bg-bg-secondary">
  <Sparkle size={14} weight="duotone" className="text-accent" />
  <span className="font-medium text-text-primary">晨报</span>
  <span className="text-text-tertiary">今日日程 {n1} · 过期任务 {n2} · 待确认 {n3}</span>
  <CaretDown size={12} className="ml-auto shrink-0" />
</button>
```

**Interaction contract:**
- Item click = navigation only (locked, no batch ops): schedule → `setActiveTab('schedule')`; task → `setActiveTab('tasks')` + `setSelectedTaskId(id)` (existing selection plumbing lights the card); memory candidate → `setChatPanelOpen(true)` (the pending-memory confirmation card already renders in the console — no new surface).
- Zero-content day (all three segments empty): the zone renders `null` — the console empty state is the hero (locked: 无内容不渲染晨报区).
- All reads are synchronous store queries wrapped in the component — no loading state, no error state exists for this surface.
- The stamp is written from the View mount (NOT from ChatPanel) — entering via ⌘K does not consume the day's report.

### Surface 4: 右键快捷 AI 动作 (UX-04)

**Locations:** new primitive `src/components/ui/ContextMenu.tsx` (Radix context-menu, styled as a DropdownMenu clone); task cards in `src/components/TaskKanban.tsx` (wrap the `data-task-card` element); knowledge doc list rows in `src/views/KnowledgeBaseView.tsx` (~:322 item rows).

**ContextMenu primitive — class strings copied verbatim from DropdownMenu.tsx:**

```tsx
// Content: 'z-tooltip min-w-[10rem] p-1 bg-bg-primary border border-border-subtle rounded-[var(--radius-md)] shadow-shadow-lg focus:outline-none'
// Item:   'relative flex cursor-pointer select-none items-center gap-2 rounded-[var(--radius-sm)] px-2.5 py-1.5 text-sm text-text-primary focus:bg-bg-secondary focus:outline-none'
// Label:  'px-2.5 py-1.5 text-xs font-medium text-text-tertiary'
```

**Usage (task card):**

```tsx
<ContextMenu>
  <ContextMenuTrigger asChild>{existingTaskCard}</ContextMenuTrigger>
  <ContextMenuContent>
    <ContextMenuLabel>AI 动作</ContextMenuLabel>
    <ContextMenuItem onSelect={() => fireTaskAction('summarize', task)}>
      <Notepad size={14} weight="duotone" className="text-accent" /> 总结此任务
    </ContextMenuItem>
    <ContextMenuItem onSelect={() => fireTaskAction('breakdown', task)}>
      <TreeStructure size={14} weight="duotone" className="text-accent" /> AI 拆解子任务
    </ContextMenuItem>
    <ContextMenuItem onSelect={() => fireTaskAction('schedule', task)}>
      <CalendarPlus size={14} weight="duotone" className="text-accent" /> 安排到日程
    </ContextMenuItem>
  </ContextMenuContent>
</ContextMenu>
```

Knowledge doc rows: identical structure, items 总结文档 (`Article`) / 存为记忆 (`Brain`) / 相关问题追问 (`ChatCircleDots`) — same icon size/weight/color discipline.

**DECISION (discretion resolved) — trigger behavior:** every action = open the ChatPanel Drawer over the CURRENT view (do NOT navigate to the agent tab — keeping the source view visible preserves context) with the console input PREFILLED but NOT sent (locked: 预填指令, user reviews then presses Enter). Mechanism: uiStore transient `pendingChatPrefill: string | null` + consume-on-read in AgentConsole (sets input state, focuses textarea, clears the slot). If the Drawer is already open, the prefill replaces nothing silently — it appends is NOT desired; it sets the input (overwrite), since each menu click is a fresh intent.

**Selection snapshot (locked):** at trigger time, read `window.getSelection()?.toString()`; when non-empty, the prefill is prefixed with it:

```
引用选区：「{snapshot trimmed to 200 chars, ellipsis}」

{instruction}
```

Empty selection → prefill is the bare instruction.

**contenteditable guard (locked):** menus register ONLY on task cards and knowledge doc list rows — the doc editor pane is NOT wrapped, so MDXEditor's native menu is untouched there. Belt-and-braces: the wrap helper checks `(event.target as HTMLElement).closest('[contenteditable="true"]')` in `onContextMenu` and skips opening (lets the native menu through) if hit.

**Interaction contract:**
- 3 actions per area (6 total) — hard cap, no more (UX-04 says 3-5; locked list is exactly 3+3).
- Menu opens on right-click with no hover prerequisite; keyboard `ContextMenu` key works via Radix default.
- Firing an action gives NO toast — the feedback IS the Drawer sliding open with a filled input.
- Menu styling must be pixel-identical to DropdownMenu (same tokens, same paddings) so it reads as the same system.
