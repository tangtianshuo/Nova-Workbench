创建 `src/stores/tabRunStore.ts`,Zustand store(不 persist——run 是瞬态):

```typescript
export type TabRunKind = 'requirement' | 'prototype' | 'code' | 'test' | 'competitor' | 'deliverable-single' | 'deliverable-batch' | 'product-skill';
export type TabRunStatus = 'queued' | 'running' | 'waiting-for-confirmation' | 'done' | 'error' | 'cancelled';

export interface TabRunEventRow { ts: number; kind: string; name?: string; summary?: string; }
export interface TabRunRecord {
  runId: string; tabId: string; kind: TabRunKind; sessionId: string;
  productId: string; status: TabRunStatus; currentStep: string;
  events: TabRunEventRow[]; startedAt: number; error?: string; candidateCount: number;
}
```

State:`runs: Record<string, TabRunRecord>`(key=runId)、`runsByTab: Record<string, string>`(tabId→活跃 runId)。

Actions:
- `startTabRun(params: { tabId: string; kind: TabRunKind; productId: string; userMessage: string; coreContext: string; sessionTitle?: string; workspaceId?: string | null; workspaceRoot?: string | null })`
  - 若 `runsByTab[tabId]` 指向 status 为 queued/running/waiting-for-confirmation 的 run,直接返回该 runId(不重复起 run)。
  - mint `runId = crypto.randomUUID()`、**独立** `sessionId = crypto.randomUUID()`(TAB-05:绝不复用聊天 sessionId;此 sessionId 不进任何会话列表 store)。
  - provider/ollamaModel 从既有配置读取(照抄 chatConsoleStore 启动 run 时的取值方式,read_first 已列)。
  - 调 `engineRun({...})`,onEvent 回调写在 store action 内部(store 级,非组件级):
    - `run_status` → 更新 status(queued/running)
    - `confirmation` → status='waiting-for-confirmation',candidateCount+1,**同时**按 chatConsoleStore 既有 confirmation 路由把候选送入全局确认队列(照抄其 data.candidate 处理;HITL 卡只走全局队列,D-05)
    - `tool_start` → events 追加行 `{ts, kind:'tool_start', name: data.name}`,currentStep = `正在调用 ${data.name}…`
    - `tool_end`/`tool_output`/`token` → events 追加行(token 只记摘要 slice(0,80))
    - `error` → status='error',error=data.message
    - `done` → status = candidateCount>0 ? 'waiting-for-confirmation' : 'done'(等待用户确认候选)
  - engineRun promise resolve → 若 status 仍为 queued/running 则置 'done';reject → 'error' + error message。结束(任何终态)后清理 `runsByTab` 仅当指向本 run。
- `cancelTabRun(runId)` → `engineCancel(runId)`,status='cancelled'(已确认落槽产物保留语义天然成立,UI 文案在 26-03)。
- `rehydrateTabRuns()` → webview 重载恢复:对每个 status 为 queued/running/waiting 的 run,按 sessionId 走既有 restore 读路径一次性拉事件重建 events/status(照抄 chatConsoleStore/restore 的按-sessionId 读取方式,read_first 定位;不做轮询)。恢复不到终态的保持原 status,由用户 cancel 或重试。
- `clearRun(runId)` → 从 runs 删除(收起面板用)。

events 数组每 run 上限 200 条,超出丢弃最旧(防十八份批量刷爆内存)。
