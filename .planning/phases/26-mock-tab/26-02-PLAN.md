**(a) scheduler.rs:**

1. 新增:
```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Priority { Interactive, Batch }
```
`Waiter` 增加 `priority: Priority` 字段。`SchedState.queue` 拆为 `queue_interactive: VecDeque<Waiter>` 与 `queue_batch: VecDeque<Waiter>`。
2. `promote` 改为:先 `while active.len() < MAX_CONCURRENT` 从 `queue_interactive` 晋升(逐个,receiver 已死则 pop 继续),interactive 空后再从 `queue_batch` 晋升(ponytail: 队内仍各自 FIFO,不做加权——够用,加权再议)。
3. `acquire` 签名增加 `priority: Priority` 参数(放在 on_queued 之前);入队按 priority 进对应队列;cancel 清理分支从两个队列 retain。默认路径:直接拿 slot 的分支与 priority 无关。
4. `snapshot`/`snapshot_detailed` 顺序改为 active 之后先 interactive 队列再 batch 队列(tray 显示排队优先级)。
5. 测试(追加到既有 #[cfg(test)]):
   - `interactive_jumps_batch_queue`:3 个 Batch run 占满 cap → 第 4 个 Batch 入队 → 1 个 Interactive 到达 → 释放一个 slot → 断言 Interactive 先获 permit(用既有测试的 waiter/permit 手法,参照 cap_three_then_fifo_promotion)。
   - `default_acquire_is_interactive_equivalent`:既有 cap_three_then_fifo_promotion 改用 Interactive 调用,断言不变(FIFO 语义回归)。
   - cancel 分支:批量排队中被 cancel 的 run 从 batch 队列移除。

**(b) commands.rs engine_run:**

1. 参数列表增加 `priority: Option<String>`(放 core_context 之后)。
2. gate 处解析:
```rust
let priority = match priority.as_deref() {
    None | Some("interactive") => scheduler::Priority::Interactive,
    Some("batch") => scheduler::Priority::Batch,
    Some(other) => return Err(AppError::ParseError(format!("unknown priority: {other}"))),
};
```
3. `state.scheduler.acquire(&run_id, cancel.clone(), priority, || {...})` 传入。其余零改动(协议增量仅此一个可选字段,默认 interactive)。

**(c) src/ai/api.ts:**

`EngineRunParams` 增加可选 `priority?: 'interactive' | 'batch'`;engineRun invoke 对象加 `priority: params.priority ?? null`。
