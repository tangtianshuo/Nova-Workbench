commands.rs(紧挨 consume_ingestion_batch_inner 之后):

```rust
/// Phase 29 (29-03, PM-02): confirm + atomically consume a pm_write candidate
/// and perform the write in one transaction. 删除类直接删行;cap-5 升级类按
/// params.action 原工具语义执行(轻写重放)。审计事件 pm_write_applied 落
/// candidate 自己的 session。Re-consume of a settled token is idempotent Ok.
#[tauri::command]
pub async fn engine_consume_pm_write(token: String, db: State<'_, EngineDb>) -> Result<Value, AppError> {
    with_conn(&db, |conn| consume_pm_write_inner(conn, &token))
}

pub fn consume_pm_write_inner(conn: &Connection, token: &str) -> Result<Value, AppError> { … }
```

inner 实现(逐句照抄 ingestion 先例的结构):
1. `confirmations::get` → 无 → Err;`candidate.kind != "pm_write"` → Err(信息带实际 kind)
2. confirm → consume(expected_params: None),AlreadySettled-when-consumed 容忍块照抄
3. `session_id = candidate.session_id.clone().unwrap_or_default()`
4. 幂等闸:已 consumed 的二次调用 — 查 agent_events 中 pm_write_applied 且 payload.confirmationToken == token 存在 → 直接 Ok(json!({"applied": false, "action": …, "alreadyApplied": true})),不重复删/写(照抄 deliverable docId+version exactly-once 思路)
5. 按 `params["action"]` 分派(全在 `conn.unchecked_transaction()` 内):
   - `"task_delete"`: title 不需要;`pm_store::delete_task(&tx, taskId)` → affected=false(行已不在)也算 applied(幂等);append 审计 `pm_write_applied` payload {action, taskId, applied:true, confirmationToken: token}
   - `"schedule_delete"`: 对称
   - 轻写升级(`"task_create"|"task_update"|"task_complete"|"schedule_create"|"schedule_update"`):从 params.args 取参,调对应 pm_store 写函数;审计 payload 带上写出的 taskId/eventId
   - 未知 action → Err
6. tx.commit() → Ok(json!({"applied": true, "action": action}))
7. 审计 event 用 `event_log::append(&tx, &EventInput{ session_id, event_type: "pm_write_applied".into(), … payload … })`,workspace_id/project_id None(correlation 不需要)

lib.rs invoke_handler 在 `engine::commands::engine_consume_ingestion_batch,` 后加 `engine::commands::engine_consume_pm_write,`。

测试写进 commands.rs mod tests(照抄 consume_ingestion_batch 测试的造数方式:mem_conn + execute("task_delete",…) 造候选)。
