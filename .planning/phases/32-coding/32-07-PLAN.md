修复 UAT test#6 blocker（及被其阻塞的 test#4/#5）：HITL 确认/拒绝（exec、fs_write、code_edit 三卡）settle 落账后 run 自动续跑，agent 继续直到给出最终回答。附带修复 fs_ops workspace-root-invalid 误报。

**架构裁定：方案 A（TS 续跑，engineRun 增加 resume 模式）。**
理由：loop_runner 每次 LLM 请求都从事件日志投影重建 messages（loop_runner.rs:276-287「Single source of truth」），`[confirmed rerun]` tool_result 落账后已在投影里——续跑 = 同 session 再跑一轮、唯一障碍是 :232 无条件 append 的 `user_message`。Rust 侧 diff 是一个 bool 字段 + 一个 if；方案 B（scheduler settle 后 spawn）需要跨 command 边界把 LLM provider/key/channel 接线搬进 scheduler，diff 大一个数量级且违背「webview 触发、引擎执行」的既有形态。三卡共用一条路径由 TS 侧单一 helper 保证。
